# P0.12 / #612 — external-link probe security boundary (offline foundation)

**Lifecycle:** v3.1.0 UNRELEASED; publication_authorized=false. Published v3.0.5 GitHub/CTAN artifacts remain immutable. This is a scoped design and preflight receipt, **not approval to perform HTTP requests or an independent security certification**.

## Delivered boundary

- tests/checks/repository/p012_probe_security_policy.py implements **only offline policy preflight and negative controls**. The file has no DNS resolver, sockets, proxy client, TLS handshake, HTTP client or worker. Static execution reports P012-PROBE-PREFLIGHT-EVIDENCE, network=0, dns=NOT_EXECUTED, http=NOT_IMPLEMENTED and security_review=PENDING.
- tests/checks/repository/external_links_contract.py remains the offline source-bound inventory (checkout SHA, fingerprint, source locations). The preflight verifies receipt structure and membership, **not the cryptographic authenticity of user-supplied receipt bytes**. A future transport must independently regenerate/verify the inventory against the *exact* trusted checkout, or require a separately authenticated receipt.
- The preflight is not proof that an external URL exists or is reachable, and it does not establish SSRF resistance in a transport that has not been written.

## Requirements for a separately reviewed opt-in HTTP implementation

1. **Explicit opt-in and egress:** a separate command requiring an affirmative network flag, an exact DNS-host allowlist, and verified network egress constraints. No network on import, static/CI, default commands, PDF validation, or release checks. Initial supported scope is HTTPS/443, ASCII canonical multi-label DNS hosts, no IP-literal URL authority, no implicit subdomain allowlisting. HTTP links remain inventoried but are not probed.
2. **DNS rebinding:** use a bounded DNS worker; reject the whole answer set if *any* resolved IPv4/IPv6 address is not public global unicast. Pin an approved IP to the **actual TCP socket**. Do not check getaddrinfo() and then pass the URL to a different client that re-resolves. Preserve the URL hostname in TLS SNI, certificate hostname verification, and HTTP Host; reject peers/routes that do not match the pinned route. Every redirect, retry and new connection needs independent resolution, validation and pinning. Additionally enforce egress denial of private, link-local and metadata networks outside the application process.
3. **Proxy isolation:** never inherit HTTP_PROXY, HTTPS_PROXY, ALL_PROXY, PAC or system proxy configuration. Do not delegate DNS or TLS to an intermediary. Test with malicious proxy environment settings. Any explicit proxy design is outside this approved initial scope.
4. **Total deadline and size caps:** one monotonic deadline per URL across DNS, connect, TLS, HEAD, redirects and conditional GET. A supervisor must kill a stalled child and persist TIMEOUT without losing earlier records. Bound concurrency, redirects (initial maximum 3), header bytes, body bytes (even if Range is ignored), output and memory. Do not consume redirect bodies automatically. Restrict GET fallback to explicitly justified HEAD failures such as 405/501, with the same global budget.
5. **Every redirect is untrusted:** before every hop reject control characters, backslashes, userinfo, unapproved host, non-HTTPS, invalid/nonstandard ports, redirect cycles and excessive hops. Relative locations resolve against the preceding approved URL. The current offline validator only approves *planned* hops, not a socket route.
6. **Incremental truthful receipts:** record source checkout SHA, inventoried fingerprint, references, URL, time, redirect chain, pinned address, HTTP result, error class, bytes read and remaining deadline. Persist per-URL results incrementally, with PARTIAL for interrupted runs and safe retries. Distinguish REACHABLE, ACCESS_RESTRICTED, NOT_FOUND, GONE, RATE_LIMITED, TIMEOUT, UNSAFE_TARGET, DNS_ERROR, TLS_ERROR and NETWORK_ERROR. A 401/403 is not a broken link; a timeout is not evidence of absence. Never save arbitrary response bodies or secrets.

## Evidence in this first slice and outstanding security gate

The offline self-test checks valid HTTPS URLs, explicit host consent, IPv4/IPv6 public DNS answers, rejected mixed public/private, public/site-local and public/reserved IPv6 answers (including `fec0::1`, `::2` and `4000::1`), and a documented allowance only for IPv4-mapped IPv6 addresses with public embedded IPv4. It rejects internal names including the exact `home.arpa` hostname, direct IP literals and legacy numeric IPv4 spellings (`0x7f.1`, octal/hexadecimal and mixed-component forms) **even when explicitly allowlisted**, malformed ports/userinfo, malformed redirect authorities caught as `UnsafeTarget`, redirects/loops, deadline expiry and inventory membership. No live DNS, TLS, proxy, socket or HTTP behavior is exercised; fake-socket coverage of DNS rebinding and actual worker termination are **outstanding**, not passed.

A future PR must implement a pinned-IP transport behind explicit opt-in and prove, using simulated socket/DNS behavior plus a separately controlled ephemeral integration environment: public-IP enforcement across redirects and retries, TLS Host/SNI/certificate correctness, proxy noninheritance, hostile redirects, slow DNS/headers/TLS, oversized responses, process kill and receipt preservation. Require independent security review or clearly documented limitations, mandatory checks on exact HEAD, guarded squash and postmerge certification. Do **not** declare SECURITY_PROBE=PASS or P0.12_GLOBAL=PASS based on this foundation.
