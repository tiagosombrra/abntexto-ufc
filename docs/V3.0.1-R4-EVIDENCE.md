## Purpose

Close the two release-blocking Web/Lite defects without changing normative predicates, locator policy, tolerance values or the intended CLI/Deep capability boundary.

## Confirmed entry defects

1. `validator/app.js` imports `./normative-catalog.js`, but the tracked `validator/` tree does not contain that module. A clean static copy of the directory therefore has an incomplete local module graph.
2. `tests/checks/normative_cross_surface.py` proves report/verdict semantics using synthetic vectors, but it does not send a real PDF through the browser's productive `analyze(file, profile)` path.

No repository evidence currently proves a public GitHub Pages deployment. R4 therefore certifies a self-contained static tree and browser execution; public hosting/deployment must not be claimed unless separately demonstrated by Git state or GitHub configuration.

## Fixed implementation decisions

- Keep `standards/catalog.json + standards/precedence.json` as normative source of truth.
- Generate and track `validator/normative-catalog.js` using `tools/normative_catalog.py --emit-web`.
- The source gate independently regenerates that module into a temporary path and requires byte-for-byte identity with the tracked browser module.
- The source gate parses relative ES-module imports and requires every referenced local file to exist inside the tracked static tree.
- Do not create a second validator implementation for testing. The same `analyze` function used by the UI is exported/exposed for browser automation.
- Browser E2E must interact with the productive `validator/index.html` file-upload/profile/analyze controls and obtain the productive report.
- Use an actual canonical/reference PDF as the positive input and a valid deliberately non-A4 PDF as the negative input.
- Positive criteria include `pdf.open=PASS` and `layout.a4=PASS`.
- Negative criteria include `layout.a4=FAIL` and top-level verdict `FAIL`.
- `font.embedded` and `pdfa.deep` must remain `MANUAL REVIEW` in Web/Lite.
- Browser code remains local-processing: no upload API.
- Reuse the three permanent workflows. No fourth workflow is added.
