## Branch and governance outcome

The hygiene program reached the intended repository steady state:

- 185 non-`main` remote refs were removed during the pruning program;
- the forensic branch manifest remains a historical pre-pruning snapshot;
- merged PR head branches are automatically deleted;
- squash is the allowed merge method;
- `main` requires pull requests, linear history and review-thread resolution;
- permanent required checks are `Static contract` and `Linux integration` under strict required-status-check policy;
- the v3 tag ruleset prevents published version tags from being moved or deleted.

These governance controls are repository policy, not release payload content.

## Permanent workflow responsibilities

The four retained workflows remain intentionally distinct:

- **Static Contract** — fast repository/source/normative contract on main PRs/pushes;
- **Linux Integration** — scoped or complete integration according to the full PR diff;
- **Linux Release Check** — release-grade reproducibility, PDF/A, distributions, current CTAN `pkgcheck` and human-review artifacts;
- **Pages** — project site and Web/Lite validator delivery.

A documentation-only tail commit cannot hide technical changes already present in a PR because Linux Integration classifies the full PR diff against `main`.
