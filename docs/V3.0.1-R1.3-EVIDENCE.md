## Bounded CI-scope correction discovered during R1.3

The active correction state is machine-readable documentation/control-plane state. Updating it alone must not force heavy integration, just as `release/v3-roadmap.json` and `docs/**` do not. Otherwise the required rule “update documentation on every material advance” mechanically launches a full Linux regression for bookkeeping changes.

The selector therefore treats `release/v3.0.1-final-corrections.json` as `docs-only`. Fail-closed behavior is preserved:

- unknown technical paths still select `complete`;
- runtime/core/standards changes still select their required scopes or `complete`;
- final/release candidate markers still force `complete`;
- orchestration-only changes still select `smoke`;
- canonical TCC chapter changes select `reference-document`.

`tests/checks/linux_integration_suites.py` and the selector self-test explicitly protect this classification.

## Typography correction after Linux #403

The #403 warnings are corrected in the teaching text rather than by relaxing `reference-document.sh`:

- `\apud` and `\textapud` are now introduced as separate command names; the prose explains the two bibliography keys and optional locators without typesetting an oversized full invocation as one monospaced token;
- `\ufcAddBibliographyResource` is shown as the command name, and `backmatter/references.bib` is shown as a separate argument/path token;
- no class implementation, bibliography semantics, normative value or warning threshold is changed.

This preserves the pedagogical information while allowing TeX normal line breaking inside the guide callout.
