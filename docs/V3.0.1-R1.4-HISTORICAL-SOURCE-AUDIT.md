## Question answered

Why does the current canonical PDF still look close to the reduced prior example instead of reflecting the requested deep reconstruction?

Because the current v3 source lineage preserved the already-reduced v2 textual corpus. The richer historical v1.1.2 model was not recovered during R1.3.

## Historical source comparison

### Root document

- v1.1.2 `documento.tex`: about 8.2 kB.
- v2.1.0 `documento.tex`: about 3.8 kB.

v2.1.0 migrated the project to the modern `ufctex/abntexto` stack and reorganized API names. That migration also coincided with a substantial simplification of the pedagogical textual corpus.

### Primary textual files

| Source role | v1.1.2 size | v2.1.0 size | Historical structural change |
|---|---:|---:|---|
| Introduction | ~2.3 kB | ~2.3 kB | `\chapter` -> `\section` |
| Theoretical foundation | ~13.2 kB | ~1.1 kB | `\chapter` + multiple concrete examples -> short `\section` |
| Related work | ~2.2 kB | ~1.0 kB | `\chapter` -> `\section` |
| Methodology | ~10.1 kB | ~0.9 kB | `\chapter` + many examples -> short `\section` |
| Results | ~6.6 kB | ~1.1 kB | project/results dual structure -> short `\section` |
| Conclusion | ~0.8 kB | ~0.4 kB | `\chapter` -> `\section` |
| Formatting examples | not a separate v1.1.2 file in the same form | ~10.2 kB | examples consolidated into one visual-catalog section |

The v2 line did not merely rename files. It moved many examples into a single formatting-catalog file and heavily reduced the research-shaped explanatory chapters.

## What existed in v1.1.2 and must be reconsidered

The richer historical source contains concrete, rendered examples and explanatory prose for:

- bibliographic citations and multiple-reference citations;
- long direct quotations;
- figures with source/legend guidance;
- tables and frames;
- cross-references;
- acronyms;
- alíneas/enumerations;
- pseudocode and legacy algorithm support;
- mathematical formulas;
- source code;
- theorem/proposition-like structures;
- question/example structures;
- project resources and schedule;
- research-results sections.

Not all old prose should be restored verbatim. Some commands, API names and normative explanations are obsolete. The correct R1.4 operation is **semantic recovery**, not rollback.

## Key lineage finding

The current v3 canonical source was rebuilt primarily from the v2-style reduced guide, not from the richer v1.1.2 teaching corpus.

That is why the recent R1.3 changes could be technically real while remaining visually modest: R1.3 added around 202 source lines and callouts to the reduced lineage instead of reconstructing the deeper historical example.

## Structural finding

v1.1.2 used `\chapter` for primary textual units. v2.1.0 changed those same roles to `\section` during the modern-stack migration.

This is historical evidence, not yet a decision to restore `\chapter`. R1.4-B must verify the current `abntexto` structural model and the desired rendered hierarchy before choosing the final command. The final acceptance criterion is the visible hierarchy/TOC, not source nostalgia.

## Recovery policy

For each old example block, classify it as one of:

- `RESTORE_ADAPTED`: pedagogically valuable and still valid after current API/normative adaptation;
- `REWRITE`: concept still required but historical content/API is obsolete;
- `KEEP_CURRENT`: current v3 explanation/example is stronger;
- `DROP_WITH_REASON`: historical example is obsolete, misleading, redundant or outside the canonical TCC.

The result must feed the final R1.2 coverage matrix.

## Current conclusion

The maintainer's observation is confirmed by Git history. The canonical PDF looks reduced because the modern lineage itself was reduced before R1.3, and R1.3 did not perform a deep historical-content recovery.

R1.4-A is complete. R1.4-B now owns the visible structural design; R1.4-C/D will restore/rewrite the pedagogical corpus and close the coverage matrix before another canonical PDF can be accepted.
