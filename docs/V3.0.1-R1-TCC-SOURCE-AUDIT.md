## Why this is not only cosmetic

The legacy names came from an earlier fictitious research-paper structure. The current document has already evolved into a normative/pedagogical reference guide, so names such as `theoretical-framework`, `methodology`, `results`, `related-work` and `conclusion` no longer describe the actual content.

Keeping those names makes the project misleading for users and makes future audit work harder because source identity no longer corresponds to rendered identity. R1.1 therefore normalizes only file identity and load order. It does not rewrite the instructional content.

## R1.2 coverage audit — required next step

R1.1 does **not** prove that the TCC is complete. R1.2 must review every current section against a pedagogical coverage matrix with four classifications:

- `ABNT_NORMATIVE`;
- `UFC_INSTITUTIONAL`;
- `PROJECT_POLICY`;
- `EXAMPLE_OR_RECOMMENDATION`.

For every major rule/topic, the matrix must record:

1. normative/institutional authority when applicable;
2. expected rendered behavior;
3. `abntexto-ufc` key/command/environment responsible;
4. test/evidence route protecting that behavior;
5. current TCC section that explains it;
6. status: complete, partial, missing, duplicate or stale.

The next sub-lot may rewrite or relocate content only after this matrix exists. This prevents another cycle where the example is simplified without an explicit record of what was lost.
